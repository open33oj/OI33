# monkey-patch 与 core 模板覆盖

> Hydro 升级时只需要回归这两份清单。`handler/patches/` 里的 patch 在启动时按 `handler/patches/index.ts` 的顺序应用；模板覆盖必须**同名同路径**。

## patches 清单

patches/ 清单

`getList`/`getListForRender`/`getById`/`User.private` 注入 oi33 字段并匿名化；`api.execute` 在 `users`（站内全局搜索与所有 uidOrName 选择器共用的用户搜索）上为 flag≥2 的查看者追加 `oi33_user.realname_name` 前缀匹配（命中项 `displayName` 显示实名，非管理员走不到该分支）；`HomeHandler.getCheckin/getCountdown` 首页数据（读取 `oi33_home_config`，纯规则在 `model/home-config-rules.ts`、存储在 `model/home-config.ts`，桶里导出 `homeConfigColl`；`ensureHomeConfig` 对 `updatedBy` 仍为 0 的纯种子文档用 `fillMissingFromSeed` 自动补上旧 YAML 里缺的日期/VIP/运势，`saveHomeConfig` 保存后即停止自动补齐）；`HomeHandler.get` 把 homepage 配置里的 `checkin`/`countdown` 两节（若存在）合并成单个 `oi33_side` 节，不存在但 `oi33_home_config.enabled` 为真时按 `column` 自动注入，位置取原节位置或所选列首（`templates/partials/homepage/oi33_side.html`：卡片标题位固定是 `[data-oi33-now]` 当前本地日期+时间行（payload.nowText 兜底 + 前端每秒刷新）；登录且拿到 checkin 数据时才渲染运势区（未认证=「认证后可签到」按钮跳个人 OI33 资料页、当天未签到=「抽取今日运势」按钮、已签到=运势文字 + `__stat` 两行打卡），随后 `─── 倒计时 ─── 行情方块 ── 拍卖链接 ── 盲盒链接`（`payload.market.blindboxCount` = 已上架且已到开放时间的盲盒数量，链接到 `/oi33/blindbox`）（各段之间只用 margin 分隔，没有分割线）；卡片内 `.typo h1` 的 GitHub 式下划线被去掉以便打卡信息与运势连成一组，上下内边距沿用 core 对称的 `.9375rem`；市场/拍卖查询失败只隐藏该块，并补齐模板里 `{% include %}` 的载荷）；`HomeHandler.getDiscussion` 与 `handler/discuss.ts` 的 `withHandlerClass('DiscussionMain')` 把题目讨论（`TYPE_PROBLEM`）从首页讨论组件与 `/discuss` 全部讨论中剔除（改由 `/oi33/discuss/problem` 板块页聚合）；`SolutionModel.getMulti` 换 sort 为 `{featured: -1, vote: -1}` 使**精华题解排在一般题解前面、组内按投票数倒序**（core 只有 `ProblemSolutionHandler.get` 一处调用它）；`ProblemSolutionHandler.get`/`ProblemSolutionRawHandler.get` 过滤/遮蔽审核中的题解（`hidden`，仅本人与 flag≥2 或 `PERM_EDIT_PROBLEM_SOLUTION` 可见），`handler/after/UserDetail` 同步过滤资料页「最近题解」；`handler/after/*` 兜底匿名化；Bearer `33tok_` 只读 token 鉴权（跳过 `/oi33/oauth/*`）；nunjucks `getTemplate` 启动竞态守卫；`system-setting.ts` 把 `SystemModel.set` 包一层：**同值写入只落库、不广播** `system/setting`（core 的 `service/monitor.ts` 每 30 分钟无脑重写 `server.center`，否则每次都会触发 ui-default 全量重建前端 bundle；真正的改动照旧广播，系统设置页自己那次显式广播也不受影响）。
